1. Problem Statement & Notation

Input

  • Triangle mesh M = (V, E, T) with vertices V, edges E, triangles T
  • Cross field R (per-triangle 4-RoSy field giving u,v directions)
  • Sizing field H (per-triangle desired quad element size)

Output

  • An Integer-Grid Map f : M_IGM -> M that is guaranteed to produce a valid quad mesh

Core Notation

Symbol Meaning
f The piecewise linear map from parametric domain to surface
f_t Restriction of f to triangle t, an affine map
∇f_t The 2x2 Jacobian of f_t (constant per triangle since f_t is affine)
A_t Area of triangle t in 3D
R_t ∈ R^{4x2} Columns are the normalized u and v directions of the cross field on triangle t
H_t = diag(w_t^{-1}, h_t^{-1}) Target anisotropic sizing (inverse of desired edge lengths in u,v)
S Set of singular vertices (nonzero angle defect)
r_ij ∈ {0,1,2,3} Rotation index for transition function between triangles t_i and t_j
t_ij ∈ Z^2 Integer translation for transition function
R_90 The 90-degree ccw rotation matrix: [[0,-1],[1,0]]
M_relaxed Mesh after solving continuous relaxation (ignoring integer constraints)
M_- Decimated coarse mesh
M^sep Decimated mesh with singularity separators added
M_int Mesh after MIQP solve (integer solution)
M_IGM Refined mesh (optional step 5)
Q Final quad mesh

Angle defect at vertex

  • Interior vertex: 2π - Σ_i α_i where α_i are incident angles
  • Boundary vertex: π - Σ_i α_i

2. Integer-Grid Maps: Definition & Conditions

Piecewise Linear Map

The map f is given per triangle as an affine map from 3 input 2D coordinates to 3 output 3D coordinates:

f_i : (u_i, v_i, w_i) ∈ R^{2×3} ↦ (p_i, q_i, r_i) ∈ R^{3×3}

Following Kälberer et al. 2007, each triangle is an individual chart. A single vertex may have multiple copies (one per incident triangle).

Condition 1: Transition Functions

The transition function from chart of t_i to chart of t_j (sharing a common edge) must be an integer-grid automorphism:

g_{i→j}(a) = R_90^{r_ij} * a + t_ij        ... (Eq. 1)

where: - r_ij ∈ {0, 1, 2, 3} (rotation by r_ij × π/2 counterclockwise) - t_ij ∈ Z^2 (integer translation) - R_90 = [[0, -1], [1, 0]] (90° ccw rotation matrix)

Implementation note: The r_ij values are determined by the cross field. Once singularities are fixed, r_ij are known constants and the constraints become linear in t_ij.

The rotation matrices for each r_ij:

R_90^0 = [[1,0],[0,1]]     (identity)
R_90^1 = [[0,-1],[1,0]]    (90° ccw)
R_90^2 = [[-1,0],[0,-1]]   (180°)
R_90^3 = [[0,1],[-1,0]]    (270° ccw = 90° cw)

Condition 2: Singular Vertex Integer Locations

All singular vertices must map to integer coordinates:

f^{-1}(s_i) ∈ Z^2    ∀ s_i ∈ S        ... (Eq. 2)

This ensures cone singularities become irregular vertices of the quad mesh (vertices with valence ≠ 4).

Condition 3: Consistent Orientation

All domain triangles (u, v, w) with u, v, w ∈ R^2 must have positive signed area:

det[v - u, w - u] > 0        ... (Eq. 3)

This prevents triangle flipping (negative Jacobian determinant) and collapse (zero determinant). Geometrically: the piecewise linear map must be locally injective everywhere.

Key property

An IGM is a bijective map between two piecewise linear 2-manifold meshes f : M_IGM → M.

3. The Quality Metric

Basic Energy (E1)

E(f) = (1/2) Σ_{t∈T} A_t * ||R_t^T ∇f_t - H_t||²_Frobenius    ... (E1)

This measures how well the parameterization: 1. Aligns with the cross-field directions (via R_t) 2. Reproduces the specified element density (via H_t)

Generalized Anisotropy Metric (E2)

E_α^k(f) = (1/2) Σ_{t∈T} A_t * ||R_t^T ∇f_t - H_t||_α^k    ... (E2)

where k ∈ 2Z^+ (positive even integer), α ∈ [0,1], and the anisotropy norm is:

||(a b; c d)||_α^k = 2α(a^k + d^k) + 2(1-α)(b^k + c^k)

Interpretation: - Diagonal elements a, d measure sizing fidelity (stretching along cross-field u,v) - Off-diagonal elements b, c measure angular deviation (shearing away from cross-field) - α = 0.5: equal weight to sizing and alignment - α < 0.5: prefer stretching along cross-field over angular deviation (good for coarse layouts with rectangular patches) - α = 0.1: recommended for quad layout generation - α = 0.5: recommended for standard quad remeshing

Despite its nonlinearity for k > 2, this is still a convex function and efficiently optimizable.

Practical choice: The paper uses k = 2 throughout (quadratic program). Higher-order norms penalize outliers more but make the problem harder.

4. The Naive MINLP

Problem (P1)

minimize  E_q(f)
subject to  (1), (2), (3)            ... (P1)

Variable count

  • 6|T| + 3|E| unknowns total
  • At least 3|E| discrete variables
  • Due to (1): 2|E| equality constraints (nonlinear in r_ij, linear in t_ij)
  • Due to (3): |T| non-convex quadratic inequality constraints
  • DOFs can be reduced along a spanning tree to O(|V|) continuous + discrete variables

Why this is intractable

  1. Constraint (1) is nonlinear due to r_ij (but becomes linear once r_ij are fixed by the cross field)
  2. Constraint (3) is non-convex (bilinear in vertex positions)
  3. The search space is enormous for typical meshes

Requirements for modern MIQP solvers

Modern branch-and-cut solvers (CPLEX, Gurobi) need: 1. Convex objective and constraints 2. Low-dimensional search space 3. Continuous relaxation close to the optimal integer solution

The paper addresses each: (1) via Section 3.1 (convex orientation), (2) via Section 3.2 (complexity reduction), (3) via Section 3.3 (singularity separation).

5. Convex Consistent Orientation

5.1 The Non-Convexity Problem

The feasible set of condition (3), {(u,v,w) ∈ R^6 : det[v-u, w-u] > 0}, is non-convex (N ⊂ R^6).

We need a conservative convex approximation C ⊂ N such that: - Every point in C satisfies (3) — no false positives - C contains a rich set of valid configurations — not too restrictive

5.2 Trisector Construction

Given a triangle T = (u_0, u_1, u_2) and a center point m inside the triangle:

Define three sectors by ccw-ordered ray vectors s_0, s_1, s_2 emanating from m:

S_i = { u ∈ R^2 : (u - m) · s_i^⊥ > 0  ∧  (u - m) · s_{i+1}^⊥ < 0 }

where: - (·)^⊥ denotes 90-degree ccw rotation: (x,y)^⊥ = (-y,x) - Index arithmetic is modulo 3 - The three sectors S_0, S_1, S_2 partition R^2

Key theorem: If vertex u_i stays strictly within sector S_i and m is an interior point, then the triangle cannot flip. The area decomposes into three sub-triangles T_i = (u_i, u_{i+1}, m), each with guaranteed positive area.

5.3 Choosing the Trisector Origin: Fermat Point

The first Fermat point m is the point inside the triangle where angles between (û_i - m) and (û_{i+1} - m) are exactly 120° each, where û_i are the reference (initial) vertex positions.

Construction: 1. Attach an equilateral triangle to each edge of the reference triangle 2. Connect each outer vertex to the opposing original vertex 3. The three connecting lines intersect at the Fermat point

Separation vectors: s_i are chosen as the bisectors of the angles at m, i.e., each s_i points from m toward û_i. Since all angles at m are 120°, the separation rays are 120° apart.

Why the Fermat point? It maximizes rotational freedom — the feasible space C allows: - Arbitrary translations - Isotropic scalings in (0, ∞) - Rotations within (-60°, 60°)

5.4 Handling Obtuse Triangles (angle > 100°)

The Fermat point exists inside the triangle only when no angle exceeds 120°. However, for angles approaching 120°, the Fermat point gets too close to a vertex, restricting the feasible space.

Solution: Virtually split triangles with any angle > 100° along the altitude at the largest angle.

Split point: d = (1-α)b + αc    (barycentric, linear in original vertices)

After splitting: - No sub-triangle has an angle > 90° - The Fermat point is well inside each sub-triangle - The split is “virtual” — no explicit mesh modification needed since d is a linear combination

5.5 Linearized Orientation Constraints (Eq. 4)

The final constraints are 6 linear inequalities per triangle (or per virtual sub-triangle):

δ_i^0 * ( (u_i - m) · s_i^⊥/||s_i^⊥|| - ε ) ≥ 0
δ_i^1 * ( -(u_i - m) · s_{i+1}^⊥/||s_{i+1}^⊥|| - ε ) ≥ 0        ... (Eq. 4)

for i = 0, 1, 2, where: - 2ε is a lower bound on the distance between two vertices of the same triangle - ε is chosen as 1% of the smallest reference edge length - δ_i^0 and δ_i^1 are normalization factors normalizing the constraint value to 1 w.r.t. the reference shape - The solver tolerance must be chosen below 2ε

Implementation: These are standard linear inequality constraints Ax ≥ b that can be fed directly to any LP/QP/MIQP solver.

5.6 Reference Triangles for Trisectors

  • Step 1 (initial parametrization): reference triangles minimize ||R_t^T ∇f_t - H_t||²
  • Steps 3, 4, 5 (after decimation): reference triangles are from the latest configuration
  • Trisectors are greedily re-initialized in every step

6. The Practical MIQP

Problem (P2)

minimize  E_α^k(f)
subject to  (1), (2), (4)            ... (P2)

Note: Condition (3) is replaced by its conservative linear approximation (4).

This is a convex MIQP: - Objective: convex quadratic (for k=2) - Constraint (1): linear (since r_ij are known from the cross field) - Constraint (2): integrality constraints on singular vertex positions - Constraint (4): linear inequalities

Branch-and-Cut

A branch-and-cut solver (CPLEX/Gurobi) explores a tree of continuous problems: - Root: the continuous relaxation (QP ignoring integer constraints) - Branching: split search space by adding x_i ≤ floor(x_i*) or x_i ≥ ceil(x_i*) for some fractional variable - Cutting: add valid inequalities (like singularity separators) to tighten the relaxation - Pruning: discard subtrees where the bound exceeds the best known solution

Key requirements for fast convergence: 1. Low node complexity → addressed by complexity reduction (Sec 3.2) 2. Initial continuous relaxation close to optimal integer solution → addressed by singularity separation (Sec 3.3)

7. Complexity Reduction

7.1 Motivation

The continuous relaxation f_relaxed is a globally smooth map except at cone singularities. In flat regions (away from singularities), the relaxation is already nearly integer. Only near singularities does integer snapping matter.

Key idea: Decimate the mesh in the 2D parametric space of M_relaxed, not in 3D. This preserves the original 3D surface exactly while drastically reducing the problem dimension.

7.2 Energy on the Decimated Mesh

After decimation, each triangle in M_- overlaps a set of triangles from M_relaxed:

E_α^k(f ∘ g) = (1/2) Σ_{t∈T_M} Σ_{s∈T_{M_-}} A_{t∩f(s)} * ||R_t^T ∇f_t ∇g_s - H_t||_α^k    ... (E3)

For isotropic, globally constant H_t, with the approximation that R_t^T ∇f_t ≈ H_t:

E_α^k(f ∘ g) ≈ (1/2) Σ_{s∈T_{M_-}} A_s * ||∇g_s - I||_α^k    ... (E4)

This avoids intersecting both triangle meshes — a major simplification.

7.3 Mesh Decimation Algorithm

Operations (all performed as isometric re-tessellation of flat 2D parametric space):

  1. Halfedge collapse: merge an edge, removing one vertex
    • Sorted by increasing edge length
    • Disallow any collapse that moves a cone singularity
  2. Edge flip: swap the diagonal of a quad formed by two adjacent triangles
    • Used to restore the Delaunay criterion [Botsch et al. 2010]
  3. Edge split: subdivide an edge into two

Strategy: 1. Perform valid halfedge collapses sorted by increasing edge length 2. Continue until no more collapses are possible 3. Flip edges violating the Delaunay criterion 4. New halfedges from flips may become collapsible → iterate 5. Result: approximately the intrinsic Delaunay triangulation of the singular vertex set

Triangle quality: Not critical. The decimated mesh typically has triangles with large aspect ratios, but this doesn’t hurt the MIQP solution. The paper favors low complexity over mesh quality and skips Delaunay refinement.

Typical reduction: From ~15,000 vertices to ~109 vertices (roughly equal to the number of singularities).

7.4 Splitting Integer-Critical Edges

After decimation, some large triangles with 3 singular vertices could force all vertices onto a line in the integer grid.

Definition: An edge is integer-critical if: - It is incident to a triangle with three singular vertices - The angle opposing the edge is > 110° (conservative threshold)

Fix: Split all integer-critical edges (each split separates two singular vertices by inserting a regular vertex). Split in order of decreasing edge length. The number of integer-critical edges decreases monotonically, so this terminates.

7.5 Maintaining the Map f_deci : M_- → M_relaxed

For each triangle t_i ∈ M_-, maintain a function:

Ψ_i(u) = (t_j, ψ_i(u))

where t_j is the image triangle in M_relaxed and ψ_i gives local coordinates. This tracks the correspondence during decimation.

Initialization: Ψ_i(u) = (t_i, u) (identity)

Collapse/flip/split update: 1. Express the neighborhood of triangles in a common chart using transition functions g 2. Update Ψ_i^new = Ψ_i ∘ g^{-1} 3. If the barycenter moves from m_o to m_n, map via ψ_i to M_relaxed and follow through triangles (t_{j1}, ..., t_{jn}) using transition functions: η = g_{j_{n-1}→j_n} ∘ ... ∘ g_{j_1→j_2} Ψ_i^new(u) = (t_{j_n}, η ∘ ψ_i(u))

8. Singularity Separation

8.1 The Problem

In the continuous relaxation, singular vertices can be arbitrarily close to each other. But in any valid IGM, their distance in Z × Z is at least 1. If the continuous relaxation clusters singularities, the branch-and-cut solver wastes time exploring infeasible subtrees.

8.2 Geodesic Disc Strategy

For each singular vertex s_i: 1. Grow a geodesic disc G_i of radius √2 within the decimated mesh M_- 2. For all singularities s_j within G_i with i < j: - Trace the shortest geodesic path P connecting s_i and s_j - If path P contains another singularity s_k ∉ {i,j}, reject (shorter candidate paths (s_i,s_k) and (s_k,s_j) already cover this) - Otherwise, add a separation constraint

Geodesic computation: Fast Marching Method [Kimmel & Sethian 1998] with the circle update [Novotni & Klein 2002], which is exact in the obstacle-free planar case.

8.3 Separator Constraints (Eq. 5)

The difference vector between two singularities in a common chart:

(Δu, Δv)^T = (u_i, v_i)^T - η(u_j, v_j)

where η is the combined transition function along the geodesic path.

Separation is performed along the axis with the larger difference: - If |Δu| ≥ |Δv|: separate along u - Otherwise: separate along v

The constraint is linearized by fixing the sign from the continuous relaxation:

{sgn(Δu)|_{M_-}} · Δu ≥ 1        (for u separators)
{sgn(Δv)|_{M_-}} · Δv ≥ 1        (for v separators)    ... (Eq. 5)

Properties: - These are linear constraints (the sign is a constant determined from M_-) - They are valid cuts: no optimal integer solution is excluded - A global scaling of the whole mesh can satisfy all constraints → always feasible - They depend linearly on translational variables introduced by transition functions

Iterative refinement: Re-computing the continuous relaxation with all separators may reveal new pairs that are now close. Iterate until stable. In rare cases, anisotropic stretching from separators may create new integer-critical edges → remove via edge splits (Section 7.4).

9. Full Algorithm Pipeline

Step-by-step (see Figure 6 in paper)

1. M → M_relaxed          Globally smooth parametrization
2. M_relaxed → M_-        Decimation in parametric space
3. M_- → M^sep            Addition of singularity separators
4. M^sep → M_int          Optimization of MIQP
5. M_int → M_IGM          (Optional) Refinement of map
6. M_IGM → Q              Quad mesh extraction

Step 1: Globally Smooth Parametrization

Solve the continuous relaxation of (P2):

minimize  E_α^k(f)
subject to  (1), (4)    [no integer constraints on singularities]

Using IPOPT (interior point method). Variables merged along dual spanning tree. One arbitrary singularity fixed to (0,0).

Step 2: Decimation in Parametric Space

  1. Map mesh to flat 2D parametric space using f_relaxed
  2. Perform halfedge collapses (increasing edge length, skip singularities)
  3. Flip non-Delaunay edges, iterate
  4. Split integer-critical edges
  5. Track Ψ functions for correspondence

Step 3: Singularity Separators

  1. For each singularity, grow geodesic disc of radius √2 in M_-
  2. For each close pair, trace shortest geodesic path
  3. Add linear separation constraint (Eq. 5)
  4. Re-solve continuous relaxation with separators
  5. Check for new close pairs, iterate until stable

Step 4: MIQP Optimization

Solve Problem (P2) on the decimated mesh M^sep:

minimize  E_α^k(f ∘ g)  ≈  (1/2) Σ_s A_s ||∇g_s - I||_α^k
subject to  (1): transition function constraints (linear)
            (2): singularity integrality (integer constraints)
            (4): orientation constraints (linear, lazy)
            (5): singularity separators (linear)

Using CPLEX (branch-and-cut). Variables merged along dual spanning tree. One singularity fixed to (0,0).

Step 5: (Optional) Refinement

Inverse of decimation: 1. Split edges in M_int at their midpoints, prioritized by decreasing edge length 2. Terminate when all edges < user tolerance (default: 1, i.e., one quad edge length) 3. Re-optimize only continuous DOFs (integers t_ij stay fixed) 4. This is a low-dimensional continuous QP, not a MIQP

Step 6: Quad Mesh Extraction

Extract the quad mesh from the integer iso-lines of the IGM. This uses standard contouring (e.g., QEx library).

10. Implementation Details

10.1 Variable Reduction via Dual Spanning Tree

For each pair of adjacent triangles sharing an edge, the transition function (1) constrains how their vertex positions relate. By selecting a dual spanning tree (spanning tree of the triangle adjacency graph), one can express all vertex positions in terms of: - A single reference frame (the root triangle) - The t_ij values on non-tree edges (cotree edges)

This eliminates redundant variables and ensures each triangle’s DOFs are expressed through the transition functions.

Total remaining DOFs: - Continuous: 2|V_-| (2D positions of decimated vertices) - Integer: ~2|S| (integer translations, roughly 2 per singularity)

10.2 Fixing a Singularity

Pin one arbitrary singularity to (0,0) to remove the global translation DOF and obtain a unique minimum. This is done with a very large penalty (~1e10) or as a hard equality constraint.

10.3 Reference Triangles for Orientation Constraints

Step 1: reference triangles minimize ||R_t^T ∇f_t - H_t||²_F (from input cross-field and sizing) Steps 3, 4, 5: reference triangles are from the latest solution configuration. Trisectors are re-initialized in every step.

10.4 Lazy Constraint Strategy

Orientation constraints (4) are typically violated for only a small fraction of triangles.

Algorithm: 1. Start with empty set of orientation constraints (4) 2. Solve the QP/MIQP 3. Check all triangles for orientation violations 4. If any violated: add constraints for all triangles with (normalized) constraint value < 0.5 5. Repeat until no violations remain

This significantly reduces runtime (e.g., 9.3 min → 4 min on the buddha model).

10.5 Features and Boundaries

Feature edges (including all boundary edges) must map to integer-grid lines: - Feature edges → linear constraints forcing the edge to lie on a u-integer or v-integer line - Feature vertices (corners) → constrained to integer locations - Feature graph = closed/open chains of mesh edges ending at feature vertices or singularities

During decimation: - Treat feature vertices like singularities (don’t move them) - Forbid halfedge collapses between vertices on different feature lines

10.6 Numerical Solver Settings

IPOPT: Interior point method for continuous QP problems (steps 1, 3, 4 relaxation, 5) - Could alternatively use CPLEX for the continuous problems if constant Hessian/Jacobian is exploited

CPLEX: Branch-and-cut for MIQP (step 4) - Restricted to k = 2 (quadratic programs) - Default settings used (could tune for performance) - Runtime dominated by the first relaxed solution

10.7 Default Parameters

Parameter Default Use

11. Data Structures for C++ Implementation

11.1 Core Data Structures

struct TriangleMesh {
    std::vector<Eigen::Vector3d> vertices_3d;   // 3D vertex positions
    std::vector<Eigen::Vector2d> vertices_2d;    // 2D parametric positions (the unknowns)
    std::vector<std::array<int, 3>> triangles;   // triangle vertex indices
    std::vector<std::array<int, 2>> edges;       // edge vertex indices
    std::vector<std::pair<int,int>> tri_adjacency; // per-edge: (tri_left, tri_right)
    std::vector<double> triangle_areas;           // A_t
};

struct CrossField {
    // Per-triangle: 4x2 matrix with columns = normalized u,v directions
    std::vector<Eigen::Matrix<double, 4, 2>> R;
};

struct SizingField {
    // Per-triangle: diag(w_t^{-1}, h_t^{-1})
    std::vector<Eigen::Matrix2d> H;
};

struct TransitionFunction {
    int r;                    // rotation index {0,1,2,3}
    Eigen::Vector2i t;        // integer translation (the integer variable)
    // Apply: g(a) = R90^r * a + t
    Eigen::Vector2d apply(const Eigen::Vector2d& a) const;
};

struct Singularity {
    int vertex_id;
    double angle_defect;      // in radians
    int index;                // angle_defect / (π/2), should be nonzero integer
};

struct TrisectorConstraint {
    int triangle_id;
    Eigen::Vector2d m;        // Fermat point (trisector origin)
    Eigen::Vector2d s[3];     // separation ray vectors
    double delta0[3];         // normalization factors δ_i^0
    double delta1[3];         // normalization factors δ_i^1
    double epsilon;           // distance tolerance
};

struct SeparatorConstraint {
    int sing_i, sing_j;       // singularity indices
    char axis;                // 'u' or 'v'
    int sign;                 // +1 or -1 (from continuous relaxation)
    // Constraint: sign * Δaxis ≥ 1
};

struct PsiFunction {
    // Maps each triangle t_i in M_- to its image in M_relaxed
    int image_triangle;       // which triangle in M_relaxed
    Eigen::Matrix2d linear;   // affine map: ψ(u) = linear * u + offset
    Eigen::Vector2d offset;
};

11.2 Algorithm Pseudocode

ALGORITHM: Integer-Grid Maps for Reliable Quad Meshing

INPUT: triangle mesh M, cross field R, sizing field H
OUTPUT: quad mesh Q

// Step 1: Continuous relaxation
S = detect_singularities(M, R)
r_ij = compute_rotation_indices(R)  // from cross field
constraints_1 = build_transition_constraints(r_ij)  // linear in t_ij, vertex positions
fix_singularity(S[0], {0, 0})
f_relaxed = solve_QP(E_alpha_k, constraints_1)  // IPOPT

// Step 2: Decimation
M_flat = flatten(M, f_relaxed)  // project to 2D parametric space
Psi = initialize_psi(M_flat)
while (can_collapse_halfedge(M_flat)):
    e = shortest_collapsible_edge(M_flat)
    collapse_halfedge(M_flat, e, Psi)
while (has_non_delaunay_edge(M_flat)):
    flip_edge(M_flat, e, Psi)
    // new edges may be collapsible, iterate
split_integer_critical_edges(M_flat, S, Psi)
M_minus = M_flat

// Step 3: Singularity separation
for each s_i in S:
    G_i = geodesic_disc(M_minus, s_i, sqrt(2))
    for each s_j in G_i with j > i:
        P = shortest_geodesic_path(M_minus, s_i, s_j)
        if no other singularity on P:
            add_separator(s_i, s_j, P)
M_sep = M_minus + separators
// Re-solve continuous relaxation with separators
f_sep = solve_QP(E_alpha_k, constraints_1 + separators)
// Check for new close pairs, iterate if needed

// Step 4: MIQP
trisectors = compute_trisectors(M_sep)   // Fermat points, rays
orientation_constraints = {}  // start empty (lazy)
repeat:
    f_int = solve_MIQP(E_alpha_k_approx, constraints_1, integrality_2,
                       orientation_constraints, separators)  // CPLEX
    violations = check_orientation(f_int, trisectors)
    if violations.empty(): break
    orientation_constraints += violations
M_int = apply(M_sep, f_int)

// Step 5: (Optional) Refinement
M_igm = M_int
while (max_edge_length(M_igm) > 1.0):
    e = longest_edge(M_igm)
    split_edge(M_igm, e)
    f_igm = solve_QP(E_alpha_k, fix_integers(M_igm))  // continuous only

// Step 6: Quad extraction
Q = extract_quads(M_igm)  // e.g., QEx library
return Q

11.3 Key Mathematical Operations

Computing the Fermat point (Weiszfeld algorithm):

Eigen::Vector2d fermat_point(const Eigen::Vector2d& A,
                              const Eigen::Vector2d& B,
                              const Eigen::Vector2d& C) {
    // Check for angles ≥ 120°
    // If angle at A ≥ 120°, return A (similarly for B, C)

    // Weiszfeld iteration
    Eigen::Vector2d m = (A + B + C) / 3.0;
    for (int iter = 0; iter < 200; iter++) {
        double dA = (m - A).norm();
        double dB = (m - B).norm();
        double dC = (m - C).norm();
        if (dA < 1e-10 || dB < 1e-10 || dC < 1e-10) break;
        double wA = 1.0/dA, wB = 1.0/dB, wC = 1.0/dC;
        double wSum = wA + wB + wC;
        m = (wA*A + wB*B + wC*C) / wSum;
    }
    return m;
}

Building a trisector constraint matrix: For each triangle with Fermat point m and separation rays s_i:

For vertex u_i (i=0,1,2):
  Constraint A (lower bound of sector i):
    (u_i - m) · s_i^⊥ / ||s_i^⊥||  ≥  ε

  Constraint B (upper bound of sector i):
    -(u_i - m) · s_{i+1}^⊥ / ||s_{i+1}^⊥||  ≥  ε

Each constraint is linear: n^T * u_i ≥ n^T * m + ε where n is the appropriate rotated/normalized ray.

Rotation matrix application:

Eigen::Matrix2d rotation_matrix(int r) {
    // R_90^r
    static const Eigen::Matrix2d R90 = (Eigen::Matrix2d() << 0, -1, 1, 0).finished();
    Eigen::Matrix2d R = Eigen::Matrix2d::Identity();
    for (int i = 0; i < r; i++) R = R90 * R;
    return R;
}

Transition function constraint (for adjacent triangles t_i, t_j sharing edge with vertices a, b):

In chart of t_i: vertex a has position p_a^i, vertex b has position p_b^i
In chart of t_j: vertex a has position p_a^j, vertex b has position p_b^j

Constraint: R_90^{r_ij} * p_a^i + t_ij = p_a^j
            R_90^{r_ij} * p_b^i + t_ij = p_b^j

These are 4 linear equations (2 per shared vertex) in the unknowns p_a^i, p_b^i, p_a^j, p_b^j, t_ij.

Appendix A: Relationship to Bommes et al. 2009 (MIQ)

The MIQ method [Bommes et al. 2009] also uses a MIQP for global parametrization but: - Uses greedy rounding instead of branch-and-cut for integer constraints - Does not guarantee orientation consistency (no trisector constraints) - Does not perform complexity reduction (full mesh as input) - Does not add singularity separation constraints

The current paper (Bommes 2013) is a strict improvement over MIQ: same energy formulation but with guaranteed validity.

Appendix B: Comparison with Lipman 2012 (BDMS)

Lipman’s “Bounded Distortion Mapping Spaces” uses a different orientation constraint: - Given affine map A = ((a+c, d-b), (b+d, a-c)), bound conformal distortion by ||(c,d)^T||_2 ≤ a * (C-1)/(C+1) with a > 0 - This is a convex cone condition on the mapping - The ∞-norm variant restricts anisotropy to w/h ≤ (√2+1)/(√2-1) ≈ 5.8

Bommes 2013 differences: - Constraints depend on the shape (reference triangle), not just the mapping - Generalizes to 3D (tetrahedra) in a straightforward way - Experimentally: the ∞-norm is fastest in branch-and-cut but cuts away solutions; 1-norm and octagon variants perform similarly to their trisector approach

Appendix C: The Volumetric Extension (Section 5)

The paper outlines extension to hexahedral meshing: - Given a valid 3D cross field, volumetric integer-grid parametrization approaches follow the same structure - For each tetrahedron: orientation constraint linearized by choosing an interior point and separating planes through each face edge - Decimation: similar strategy with 3D mesh simplification - Separator generation: between singular lines (not just singular points) - The MIQP structure is identical

## 1. Problem Statement & Notation

### Input
- Triangle mesh `M = (V, E, T)` with vertices `V`, edges `E`, triangles `T`
- Cross field `R` (per-triangle 4-RoSy field giving u,v directions)
- Sizing field `H` (per-triangle desired quad element size)

### Output
- An Integer-Grid Map `f : M_IGM -> M` that is guaranteed to produce a valid quad mesh

### Core Notation

| Symbol | Meaning |
|--------|---------|
| `f` | The piecewise linear map from parametric domain to surface |
| `f_t` | Restriction of `f` to triangle `t`, an affine map |
| `∇f_t` | The 2x2 Jacobian of `f_t` (constant per triangle since `f_t` is affine) |
| `A_t` | Area of triangle `t` in 3D |
| `R_t ∈ R^{4x2}` | Columns are the normalized u and v directions of the cross field on triangle `t` |

- Interior vertex: `2π - Σ_i α_i` where `α_i` are incident angles

## 2. Integer-Grid Maps: Definition & Conditions

### Piecewise Linear Map

The map `f` is given per triangle as an affine map from 3 input 2D coordinates to 3 output 3D coordinates:

```
f_i : (u_i, v_i, w_i) ∈ R^{2×3} ↦ (p_i, q_i, r_i) ∈ R^{3×3}
```

Following Kälberer et al. 2007, each triangle is an individual chart. A single vertex may have multiple copies (one per incident triangle).

### Condition 1: Transition Functions

The transition function from chart of `t_i` to chart of `t_j` (sharing a common edge) must be an integer-grid automorphism:

```
g_{i→j}(a) = R_90^{r_ij} * a + t_ij        ... (Eq. 1)
```

where:
- `r_ij ∈ {0, 1, 2, 3}` (rotation by r_ij × π/2 counterclockwise)
- `t_ij ∈ Z^2` (integer translation)
- `R_90 = [[0, -1], [1, 0]]` (90° ccw rotation matrix)

**Implementation note**: The `r_ij` values are determined by the cross field. Once singularities are fixed, `r_ij` are known constants and the constraints become **linear** in `t_ij`.

The rotation matrices for each `r_ij`:
```
R_90^0 = [[1,0],[0,1]]     (identity)
R_90^1 = [[0,-1],[1,0]]    (90° ccw)
R_90^2 = [[-1,0],[0,-1]]   (180°)
R_90^3 = [[0,1],[-1,0]]    (270° ccw = 90° cw)
```

### Condition 2: Singular Vertex Integer Locations

All singular vertices must map to integer coordinates:

```
f^{-1}(s_i) ∈ Z^2    ∀ s_i ∈ S        ... (Eq. 2)
```

This ensures cone singularities become irregular vertices of the quad mesh (vertices with valence ≠ 4).

### Condition 3: Consistent Orientation

All domain triangles `(u, v, w)` with `u, v, w ∈ R^2` must have positive signed area:

```
det[v - u, w - u] > 0        ... (Eq. 3)
```

This prevents triangle flipping (negative Jacobian determinant) and collapse (zero determinant). Geometrically: the piecewise linear map must be **locally injective** everywhere.

### Key property
An IGM is a **bijective** map between two piecewise linear 2-manifold meshes `f : M_IGM → M`.

## 3. The Quality Metric

### Basic Energy (E1)

```
E(f) = (1/2) Σ_{t∈T} A_t * ||R_t^T ∇f_t - H_t||²_Frobenius    ... (E1)
```

This measures how well the parameterization:
1. Aligns with the cross-field directions (via `R_t`)
2. Reproduces the specified element density (via `H_t`)

### Generalized Anisotropy Metric (E2)

```
E_α^k(f) = (1/2) Σ_{t∈T} A_t * ||R_t^T ∇f_t - H_t||_α^k    ... (E2)
```

where `k ∈ 2Z^+` (positive even integer), `α ∈ [0,1]`, and the anisotropy norm is:

```
||(a b; c d)||_α^k = 2α(a^k + d^k) + 2(1-α)(b^k + c^k)
```

**Interpretation**:
- Diagonal elements `a, d` measure **sizing** fidelity (stretching along cross-field u,v)
- Off-diagonal elements `b, c` measure **angular** deviation (shearing away from cross-field)
- `α = 0.5`: equal weight to sizing and alignment
- `α < 0.5`: prefer stretching along cross-field over angular deviation (good for coarse layouts with rectangular patches)
- `α = 0.1`: recommended for quad layout generation
- `α = 0.5`: recommended for standard quad remeshing

Despite its nonlinearity for `k > 2`, this is still a **convex** function and efficiently optimizable.

**Practical choice**: The paper uses `k = 2` throughout (quadratic program). Higher-order norms penalize outliers more but make the problem harder.

## 4. The Naive MINLP

### Problem (P1)

```
minimize  E_q(f)
subject to  (1), (2), (3)            ... (P1)
```

### Variable count
- `6|T| + 3|E|` unknowns total
- At least `3|E|` discrete variables
- Due to (1): `2|E|` equality constraints (nonlinear in `r_ij`, linear in `t_ij`)
- Due to (3): `|T|` non-convex quadratic inequality constraints
- DOFs can be reduced along a spanning tree to `O(|V|)` continuous + discrete variables

### Why this is intractable
1. Constraint (1) is **nonlinear** due to `r_ij` (but becomes linear once `r_ij` are fixed by the cross field)
2. Constraint (3) is **non-convex** (bilinear in vertex positions)
3. The search space is enormous for typical meshes

### Requirements for modern MIQP solvers
Modern branch-and-cut solvers (CPLEX, Gurobi) need:
1. **Convex** objective and constraints
2. **Low-dimensional** search space
3. Continuous relaxation **close** to the optimal integer solution

The paper addresses each: (1) via Section 3.1 (convex orientation), (2) via Section 3.2 (complexity reduction), (3) via Section 3.3 (singularity separation).

## 5. Convex Consistent Orientation

### 5.1 The Non-Convexity Problem

The feasible set of condition (3), `{(u,v,w) ∈ R^6 : det[v-u, w-u] > 0}`, is **non-convex** (N ⊂ R^6).

We need a **conservative convex approximation** C ⊂ N such that:
- Every point in C satisfies (3) — **no false positives**
- C contains a rich set of valid configurations — **not too restrictive**

### 5.2 Trisector Construction

Given a triangle `T = (u_0, u_1, u_2)` and a center point `m` inside the triangle:

Define three sectors by ccw-ordered ray vectors `s_0, s_1, s_2` emanating from `m`:

```
S_i = { u ∈ R^2 : (u - m) · s_i^⊥ > 0  ∧  (u - m) · s_{i+1}^⊥ < 0 }
```

where:
- `(·)^⊥` denotes 90-degree ccw rotation: `(x,y)^⊥ = (-y,x)`
- Index arithmetic is modulo 3
- The three sectors `S_0, S_1, S_2` partition R^2

**Key theorem**: If vertex `u_i` stays strictly within sector `S_i` and `m` is an interior point, then the triangle **cannot flip**. The area decomposes into three sub-triangles `T_i = (u_i, u_{i+1}, m)`, each with guaranteed positive area.

### 5.3 Choosing the Trisector Origin: Fermat Point

The **first Fermat point** `m` is the point inside the triangle where angles between `(û_i - m)` and `(û_{i+1} - m)` are exactly **120°** each, where `û_i` are the reference (initial) vertex positions.

**Construction**:
1. Attach an equilateral triangle to each edge of the reference triangle
2. Connect each outer vertex to the opposing original vertex
3. The three connecting lines intersect at the Fermat point

**Separation vectors**: `s_i` are chosen as the **bisectors** of the angles at `m`, i.e., each `s_i` points from `m` toward `û_i`. Since all angles at `m` are 120°, the separation rays are 120° apart.

**Why the Fermat point?** It maximizes rotational freedom — the feasible space C allows:
- Arbitrary translations
- Isotropic scalings in `(0, ∞)`
- Rotations within `(-60°, 60°)`

### 5.4 Handling Obtuse Triangles (angle > 100°)

The Fermat point exists inside the triangle only when **no angle exceeds 120°**. However, for angles approaching 120°, the Fermat point gets too close to a vertex, restricting the feasible space.

**Solution**: Virtually split triangles with any angle > 100° along the altitude at the largest angle.

```
Split point: d = (1-α)b + αc    (barycentric, linear in original vertices)
```

After splitting:
- No sub-triangle has an angle > 90°
- The Fermat point is well inside each sub-triangle
- The split is "virtual" — no explicit mesh modification needed since `d` is a linear combination

### 5.5 Linearized Orientation Constraints (Eq. 4)

The final constraints are **6 linear inequalities per triangle** (or per virtual sub-triangle):

```
δ_i^0 * ( (u_i - m) · s_i^⊥/||s_i^⊥|| - ε ) ≥ 0
δ_i^1 * ( -(u_i - m) · s_{i+1}^⊥/||s_{i+1}^⊥|| - ε ) ≥ 0        ... (Eq. 4)
```

for `i = 0, 1, 2`, where:
- `2ε` is a lower bound on the distance between two vertices of the same triangle
- `ε` is chosen as 1% of the smallest reference edge length
- `δ_i^0` and `δ_i^1` are **normalization factors** normalizing the constraint value to 1 w.r.t. the reference shape
- The solver tolerance must be chosen below `2ε`

**Implementation**: These are standard linear inequality constraints `Ax ≥ b` that can be fed directly to any LP/QP/MIQP solver.

### 5.6 Reference Triangles for Trisectors

- **Step 1** (initial parametrization): reference triangles minimize `||R_t^T ∇f_t - H_t||²`
- **Steps 3, 4, 5** (after decimation): reference triangles are from the latest configuration
- Trisectors are greedily re-initialized in every step

## 6. The Practical MIQP

### Problem (P2)

```
minimize  E_α^k(f)
subject to  (1), (2), (4)            ... (P2)
```

Note: Condition (3) is replaced by its conservative linear approximation (4).

This is a **convex** MIQP:
- Objective: convex quadratic (for k=2)
- Constraint (1): linear (since `r_ij` are known from the cross field)
- Constraint (2): integrality constraints on singular vertex positions
- Constraint (4): linear inequalities

### Branch-and-Cut

A branch-and-cut solver (CPLEX/Gurobi) explores a tree of continuous problems:
- **Root**: the continuous relaxation (QP ignoring integer constraints)
- **Branching**: split search space by adding `x_i ≤ floor(x_i*)` or `x_i ≥ ceil(x_i*)` for some fractional variable
- **Cutting**: add valid inequalities (like singularity separators) to tighten the relaxation
- **Pruning**: discard subtrees where the bound exceeds the best known solution

**Key requirements for fast convergence**:
1. Low node complexity → addressed by complexity reduction (Sec 3.2)
2. Initial continuous relaxation close to optimal integer solution → addressed by singularity separation (Sec 3.3)

## 7. Complexity Reduction

### 7.1 Motivation

The continuous relaxation `f_relaxed` is a globally smooth map except at cone singularities. In flat regions (away from singularities), the relaxation is already nearly integer. Only near singularities does integer snapping matter.

**Key idea**: Decimate the mesh in the **2D parametric space** of `M_relaxed`, not in 3D. This preserves the original 3D surface exactly while drastically reducing the problem dimension.

### 7.2 Energy on the Decimated Mesh

After decimation, each triangle in `M_-` overlaps a set of triangles from `M_relaxed`:

```
E_α^k(f ∘ g) = (1/2) Σ_{t∈T_M} Σ_{s∈T_{M_-}} A_{t∩f(s)} * ||R_t^T ∇f_t ∇g_s - H_t||_α^k    ... (E3)
```

For isotropic, globally constant `H_t`, with the approximation that `R_t^T ∇f_t ≈ H_t`:

```
E_α^k(f ∘ g) ≈ (1/2) Σ_{s∈T_{M_-}} A_s * ||∇g_s - I||_α^k    ... (E4)
```

This avoids intersecting both triangle meshes — a major simplification.

### 7.3 Mesh Decimation Algorithm

**Operations** (all performed as isometric re-tessellation of flat 2D parametric space):

1. **Halfedge collapse**: merge an edge, removing one vertex
   - Sorted by **increasing edge length**
   - Disallow any collapse that moves a **cone singularity**
2. **Edge flip**: swap the diagonal of a quad formed by two adjacent triangles
   - Used to restore the **Delaunay criterion** [Botsch et al. 2010]
3. **Edge split**: subdivide an edge into two

**Strategy**:
1. Perform valid halfedge collapses sorted by increasing edge length
2. Continue until no more collapses are possible
3. Flip edges violating the Delaunay criterion
4. New halfedges from flips may become collapsible → iterate
5. Result: approximately the **intrinsic Delaunay triangulation** of the singular vertex set

**Triangle quality**: Not critical. The decimated mesh typically has triangles with large aspect ratios, but this doesn't hurt the MIQP solution. The paper **favors low complexity over mesh quality** and skips Delaunay refinement.

**Typical reduction**: From ~15,000 vertices to ~109 vertices (roughly equal to the number of singularities).

### 7.4 Splitting Integer-Critical Edges

After decimation, some large triangles with 3 singular vertices could force all vertices onto a line in the integer grid.

**Definition**: An edge is **integer-critical** if:
- It is incident to a triangle with **three singular vertices**
- The angle opposing the edge is **> 110°** (conservative threshold)

**Fix**: Split all integer-critical edges (each split separates two singular vertices by inserting a regular vertex). Split in order of **decreasing** edge length. The number of integer-critical edges decreases monotonically, so this terminates.

### 7.5 Maintaining the Map `f_deci : M_- → M_relaxed`

For each triangle `t_i ∈ M_-`, maintain a function:

```
Ψ_i(u) = (t_j, ψ_i(u))
```

where `t_j` is the image triangle in `M_relaxed` and `ψ_i` gives local coordinates. This tracks the correspondence during decimation.

**Initialization**: `Ψ_i(u) = (t_i, u)` (identity)

**Collapse/flip/split update**:
1. Express the neighborhood of triangles in a common chart using transition functions `g`
2. Update `Ψ_i^new = Ψ_i ∘ g^{-1}`
3. If the barycenter moves from `m_o` to `m_n`, map via `ψ_i` to `M_relaxed` and follow through triangles `(t_{j1}, ..., t_{jn})` using transition functions:
   ```
   η = g_{j_{n-1}→j_n} ∘ ... ∘ g_{j_1→j_2}
   Ψ_i^new(u) = (t_{j_n}, η ∘ ψ_i(u))
   ```

## 8. Singularity Separation

### 8.1 The Problem

In the continuous relaxation, singular vertices can be **arbitrarily close** to each other. But in any valid IGM, their distance in `Z × Z` is **at least 1**. If the continuous relaxation clusters singularities, the branch-and-cut solver wastes time exploring infeasible subtrees.

### 8.2 Geodesic Disc Strategy

For each singular vertex `s_i`:
1. Grow a geodesic disc `G_i` of radius `√2` within the decimated mesh `M_-`
2. For all singularities `s_j` within `G_i` with `i < j`:
   - Trace the **shortest geodesic path** `P` connecting `s_i` and `s_j`
   - If path `P` contains another singularity `s_k ∉ {i,j}`, reject (shorter candidate paths `(s_i,s_k)` and `(s_k,s_j)` already cover this)
   - Otherwise, add a separation constraint

**Geodesic computation**: Fast Marching Method [Kimmel & Sethian 1998] with the circle update [Novotni & Klein 2002], which is exact in the obstacle-free planar case.

### 8.3 Separator Constraints (Eq. 5)

The difference vector between two singularities in a common chart:

```
(Δu, Δv)^T = (u_i, v_i)^T - η(u_j, v_j)
```

where `η` is the combined transition function along the geodesic path.

Separation is performed along the axis with the **larger** difference:
- If `|Δu| ≥ |Δv|`: separate along u
- Otherwise: separate along v

The constraint is linearized by **fixing the sign** from the continuous relaxation:

```
{sgn(Δu)|_{M_-}} · Δu ≥ 1        (for u separators)
{sgn(Δv)|_{M_-}} · Δv ≥ 1        (for v separators)    ... (Eq. 5)
```

**Properties**:
- These are **linear** constraints (the sign is a constant determined from `M_-`)
- They are **valid cuts**: no optimal integer solution is excluded
- A global scaling of the whole mesh can satisfy all constraints → always feasible
- They depend linearly on translational variables introduced by transition functions

**Iterative refinement**: Re-computing the continuous relaxation with all separators may reveal new pairs that are now close. Iterate until stable. In rare cases, anisotropic stretching from separators may create new integer-critical edges → remove via edge splits (Section 7.4).

## 9. Full Algorithm Pipeline

### Step-by-step (see Figure 6 in paper)

```
1. M → M_relaxed          Globally smooth parametrization
2. M_relaxed → M_-        Decimation in parametric space
3. M_- → M^sep            Addition of singularity separators
4. M^sep → M_int          Optimization of MIQP
5. M_int → M_IGM          (Optional) Refinement of map
6. M_IGM → Q              Quad mesh extraction
```

### Step 1: Globally Smooth Parametrization

Solve the continuous relaxation of (P2):

```
minimize  E_α^k(f)
subject to  (1), (4)    [no integer constraints on singularities]
```

Using IPOPT (interior point method). Variables merged along dual spanning tree. One arbitrary singularity fixed to (0,0).

### Step 2: Decimation in Parametric Space

1. Map mesh to flat 2D parametric space using `f_relaxed`
2. Perform halfedge collapses (increasing edge length, skip singularities)
3. Flip non-Delaunay edges, iterate
4. Split integer-critical edges
5. Track `Ψ` functions for correspondence

### Step 3: Singularity Separators

1. For each singularity, grow geodesic disc of radius `√2` in `M_-`
2. For each close pair, trace shortest geodesic path
3. Add linear separation constraint (Eq. 5)
4. Re-solve continuous relaxation with separators
5. Check for new close pairs, iterate until stable

### Step 4: MIQP Optimization

Solve Problem (P2) on the decimated mesh `M^sep`:

```
minimize  E_α^k(f ∘ g)  ≈  (1/2) Σ_s A_s ||∇g_s - I||_α^k
subject to  (1): transition function constraints (linear)
            (2): singularity integrality (integer constraints)
            (4): orientation constraints (linear, lazy)
            (5): singularity separators (linear)
```

Using CPLEX (branch-and-cut). Variables merged along dual spanning tree. One singularity fixed to (0,0).

### Step 5: (Optional) Refinement

Inverse of decimation:
1. Split edges in `M_int` at their midpoints, prioritized by **decreasing edge length**
2. Terminate when all edges < user tolerance (default: 1, i.e., one quad edge length)
3. Re-optimize **only continuous DOFs** (integers `t_ij` stay fixed)
4. This is a low-dimensional continuous QP, not a MIQP

### Step 6: Quad Mesh Extraction

Extract the quad mesh from the integer iso-lines of the IGM. This uses standard contouring (e.g., QEx library).

## 10. Implementation Details

### 10.1 Variable Reduction via Dual Spanning Tree

For each pair of adjacent triangles sharing an edge, the transition function (1) constrains how their vertex positions relate. By selecting a **dual spanning tree** (spanning tree of the triangle adjacency graph), one can express all vertex positions in terms of:
- A single reference frame (the root triangle)
- The `t_ij` values on **non-tree edges** (cotree edges)

This eliminates redundant variables and ensures each triangle's DOFs are expressed through the transition functions.

**Total remaining DOFs**:
- Continuous: `2|V_-|` (2D positions of decimated vertices)
- Integer: `~2|S|` (integer translations, roughly 2 per singularity)

### 10.2 Fixing a Singularity

Pin one arbitrary singularity to `(0,0)` to remove the global translation DOF and obtain a unique minimum. This is done with a very large penalty (~1e10) or as a hard equality constraint.

### 10.3 Reference Triangles for Orientation Constraints

**Step 1**: reference triangles minimize `||R_t^T ∇f_t - H_t||²_F` (from input cross-field and sizing)
**Steps 3, 4, 5**: reference triangles are from the latest solution configuration. Trisectors are re-initialized in every step.

### 10.4 Lazy Constraint Strategy

Orientation constraints (4) are typically violated for only a **small fraction** of triangles.

**Algorithm**:
1. Start with **empty** set of orientation constraints (4)
2. Solve the QP/MIQP
3. Check all triangles for orientation violations
4. If any violated: add constraints for all triangles with (normalized) constraint value < 0.5
5. Repeat until no violations remain

This significantly reduces runtime (e.g., 9.3 min → 4 min on the buddha model).

### 10.5 Features and Boundaries

Feature edges (including all boundary edges) must map to **integer-grid lines**:
- Feature edges → linear constraints forcing the edge to lie on a u-integer or v-integer line
- Feature vertices (corners) → constrained to integer locations
- Feature graph = closed/open chains of mesh edges ending at feature vertices or singularities

During decimation:
- Treat feature vertices like singularities (don't move them)
- Forbid halfedge collapses between vertices on **different** feature lines

### 10.6 Numerical Solver Settings

**IPOPT**: Interior point method for continuous QP problems (steps 1, 3, 4 relaxation, 5)
- Could alternatively use CPLEX for the continuous problems if constant Hessian/Jacobian is exploited

**CPLEX**: Branch-and-cut for MIQP (step 4)
- Restricted to `k = 2` (quadratic programs)
- Default settings used (could tune for performance)
- Runtime dominated by the first relaxed solution

### 10.7 Default Parameters

| Parameter | Default | Use |
|-----------|---------|-----|
| `k` | 2 | Norm order (quadratic) |
| `α` | 0.1 (coarse layout), 0.5 (fine remeshing) | Anisotropy weight |
| Virtual split threshold | 100° | When to split obtuse triangles |
| Integer-critical threshold | 110° | When to split integer-critical edges |
| Geodesic disc radius | `√2` | For singularity separation |
| `ε` | 1% of smallest ref edge | Floating point tolerance for orientation |
| Refinement edge tolerance | 1.0 | When to stop optional refinement |

### 11.2 Algorithm Pseudocode

```
ALGORITHM: Integer-Grid Maps for Reliable Quad Meshing

INPUT: triangle mesh M, cross field R, sizing field H
OUTPUT: quad mesh Q

// Step 1: Continuous relaxation
S = detect_singularities(M, R)
r_ij = compute_rotation_indices(R)  // from cross field
constraints_1 = build_transition_constraints(r_ij)  // linear in t_ij, vertex positions
fix_singularity(S[0], {0, 0})
f_relaxed = solve_QP(E_alpha_k, constraints_1)  // IPOPT

// Step 2: Decimation
M_flat = flatten(M, f_relaxed)  // project to 2D parametric space
Psi = initialize_psi(M_flat)
while (can_collapse_halfedge(M_flat)):
    e = shortest_collapsible_edge(M_flat)
    collapse_halfedge(M_flat, e, Psi)
while (has_non_delaunay_edge(M_flat)):
    flip_edge(M_flat, e, Psi)
    // new edges may be collapsible, iterate
split_integer_critical_edges(M_flat, S, Psi)
M_minus = M_flat

// Step 3: Singularity separation
for each s_i in S:
    G_i = geodesic_disc(M_minus, s_i, sqrt(2))
    for each s_j in G_i with j > i:
        P = shortest_geodesic_path(M_minus, s_i, s_j)
        if no other singularity on P:
            add_separator(s_i, s_j, P)
M_sep = M_minus + separators
// Re-solve continuous relaxation with separators
f_sep = solve_QP(E_alpha_k, constraints_1 + separators)
// Check for new close pairs, iterate if needed

// Step 4: MIQP
trisectors = compute_trisectors(M_sep)   // Fermat points, rays
orientation_constraints = {}  // start empty (lazy)
repeat:
    f_int = solve_MIQP(E_alpha_k_approx, constraints_1, integrality_2,
                       orientation_constraints, separators)  // CPLEX
    violations = check_orientation(f_int, trisectors)
    if violations.empty(): break
    orientation_constraints += violations
M_int = apply(M_sep, f_int)

// Step 5: (Optional) Refinement
M_igm = M_int
while (max_edge_length(M_igm) > 1.0):
    e = longest_edge(M_igm)
    split_edge(M_igm, e)
    f_igm = solve_QP(E_alpha_k, fix_integers(M_igm))  // continuous only

// Step 6: Quad extraction
Q = extract_quads(M_igm)  // e.g., QEx library
return Q
```

### 11.3 Key Mathematical Operations

**Computing the Fermat point** (Weiszfeld algorithm):
```cpp
Eigen::Vector2d fermat_point(const Eigen::Vector2d& A,
                              const Eigen::Vector2d& B,
                              const Eigen::Vector2d& C) {
    // Check for angles ≥ 120°
    // If angle at A ≥ 120°, return A (similarly for B, C)

    // Weiszfeld iteration
    Eigen::Vector2d m = (A + B + C) / 3.0;
    for (int iter = 0; iter < 200; iter++) {
        double dA = (m - A).norm();
        double dB = (m - B).norm();
        double dC = (m - C).norm();
        if (dA < 1e-10 || dB < 1e-10 || dC < 1e-10) break;
        double wA = 1.0/dA, wB = 1.0/dB, wC = 1.0/dC;
        double wSum = wA + wB + wC;
        m = (wA*A + wB*B + wC*C) / wSum;
    }
    return m;
}
```

**Building a trisector constraint matrix**:
For each triangle with Fermat point `m` and separation rays `s_i`:
```
For vertex u_i (i=0,1,2):
  Constraint A (lower bound of sector i):
    (u_i - m) · s_i^⊥ / ||s_i^⊥||  ≥  ε

  Constraint B (upper bound of sector i):
    -(u_i - m) · s_{i+1}^⊥ / ||s_{i+1}^⊥||  ≥  ε
```

Each constraint is linear: `n^T * u_i ≥ n^T * m + ε` where `n` is the appropriate rotated/normalized ray.

**Rotation matrix application**:
```cpp
Eigen::Matrix2d rotation_matrix(int r) {
    // R_90^r
    static const Eigen::Matrix2d R90 = (Eigen::Matrix2d() << 0, -1, 1, 0).finished();
    Eigen::Matrix2d R = Eigen::Matrix2d::Identity();
    for (int i = 0; i < r; i++) R = R90 * R;
    return R;
}
```

**Transition function constraint** (for adjacent triangles t_i, t_j sharing edge with vertices a, b):
```
In chart of t_i: vertex a has position p_a^i, vertex b has position p_b^i
In chart of t_j: vertex a has position p_a^j, vertex b has position p_b^j

Constraint: R_90^{r_ij} * p_a^i + t_ij = p_a^j
            R_90^{r_ij} * p_b^i + t_ij = p_b^j
```
These are 4 linear equations (2 per shared vertex) in the unknowns `p_a^i, p_b^i, p_a^j, p_b^j, t_ij`.

## Appendix A: Relationship to Bommes et al. 2009 (MIQ)

The MIQ method [Bommes et al. 2009] also uses a MIQP for global parametrization but:
- Uses **greedy rounding** instead of branch-and-cut for integer constraints
- Does **not** guarantee orientation consistency (no trisector constraints)
- Does **not** perform complexity reduction (full mesh as input)
- Does **not** add singularity separation constraints

The current paper (Bommes 2013) is a **strict improvement** over MIQ: same energy formulation but with guaranteed validity.

## Appendix B: Comparison with Lipman 2012 (BDMS)

Lipman's "Bounded Distortion Mapping Spaces" uses a different orientation constraint:
- Given affine map `A = ((a+c, d-b), (b+d, a-c))`, bound conformal distortion by `||(c,d)^T||_2 ≤ a * (C-1)/(C+1)` with `a > 0`
- This is a convex cone condition on the mapping
- The ∞-norm variant restricts anisotropy to `w/h ≤ (√2+1)/(√2-1) ≈ 5.8`

Bommes 2013 differences:
- Constraints depend on the **shape** (reference triangle), not just the mapping
- Generalizes to 3D (tetrahedra) in a straightforward way
- Experimentally: the ∞-norm is fastest in branch-and-cut but cuts away solutions; 1-norm and octagon variants perform similarly to their trisector approach

## Appendix C: The Volumetric Extension (Section 5)

The paper outlines extension to **hexahedral meshing**:
- Given a valid 3D cross field, volumetric integer-grid parametrization approaches follow the same structure
- For each **tetrahedron**: orientation constraint linearized by choosing an interior point and separating planes through each face edge
- Decimation: similar strategy with 3D mesh simplification
- Separator generation: between singular lines (not just singular points)
- The MIQP structure is identical
